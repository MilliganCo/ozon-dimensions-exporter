# Ozon Dimensions Exporter

Локальная CSV-выгрузка габаритов и веса товаров через endpoints списка товаров и атрибутов Seller API, использованные в исходном скрипте. Размеры приводятся к миллиметрам, вес — к граммам; исходные значения сохраняются в отдельных колонках.

Работа с актуальным Seller API и реальным кабинетом не проверялась. Проверки этой публикационной копии используют только синтетические ответы и блокируют сетевые запросы.

## Установка и личная конфигурация

Нужен Python 3.10+.

```powershell
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В своей локальной `.env` заполните `OZON_CLIENT_ID` и `OZON_API_KEY`, затем запускайте явно:

```powershell
python ozon_dims_weight_to_csv.py --env-file .env --out export.csv
```

Также поддерживаются переменные окружения текущего процесса. Автоматического поиска `.env` в родительских папках нет. Значения `--client-id`/`--api-key` сохранены для совместимости; приватный файл/окружение удобнее для ключа, который иначе попадет в историю команд.

## Извлечение значений

- Прямые поля `depth`/`length`, `width`, `height`, `weight` имеют приоритет.
- Вложенные `dimensions`/`dimension` поддерживают `unit` или `dimension_unit`; уже записанная единица в текстовом значении сохраняется.
- Для отсутствующих полей используются именованные атрибуты: сначала упаковочные названия, затем общие. ID атрибута без понятного имени сам по себе не задает его смысл.
- Поддержаны одиночные числа с точкой/запятой и сокращениями `mm/мм`, `cm/см`, `m/м`, `mg/мг`, `g/г/гр`, `kg/кг`, включая запись без пробела. Значения без единицы считаются мм/г. Неизвестные единицы, составные и отрицательные значения дают пустое числовое поле; ноль сохраняется как переданное значение.
- `source` показывает происхождение исходных значений, а не гарантию их корректности.

`--list-limit` и `--batch-size` принимают значения 1–1000. Пагинация останавливается на пустой странице или повторении текущего курсора; цикл между разными курсорами вызывает ошибку.

## Проверки и ограничения

```powershell
python -B -m unittest discover -s tests -v
```

Проверяются единицы/приоритеты, разные обертки JSON, mock-пагинация, отсутствие автоматического поиска конфигурации и CSV на полностью вымышленных данных.

HTTP retry и совместимость реальных ответов не подтверждены. Подстрочный поиск имен атрибутов остается эвристикой. CSV строится по товарам, полученным в ответах атрибутов; полноту каталога нужно сверять отдельно. Существующий `--out` перезаписывается. `--debug` и `--save-raw` могут сохранять товарные данные; сохранение raw ограничено первым образцом ответа, а не полным архивом всех страниц. Такие локальные выгрузки исключены из Git.
